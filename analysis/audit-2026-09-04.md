Title: Documentation audit — the evidence trail
Subtitle: PRE_RELEASE 80. What was wrong, what it was checked against, and what now stops it happening again.

This file is the record of the W1.0-0 documentation audit. It is not part of
any set and does not ship. It exists so a correction can be checked without
repeating the measurement, and so that a claim verified as **already correct**
is not re-investigated by the next reader.

**The standard applied.** Every factual claim was checked against the installed
image at `C:\Program Files\SD` and `C:\ProgramData\SD`, or against the source
that produced it. `assert-current` exited 0 at the start, with the install
dated 4 Sep 2026 20:42:10, so source and install agreed throughout.

**The owner's two directives, 4 Sep 2026**, which set the shape of the work:

> Validate every setting, command, etc. against the current source code. Do not
> include documentation for features the source code no longer supports.

> There may be new features that are not documented, that needs to be
> considered too.

The second is why the audit produced checkers rather than corrections. A pass
that only asked "is everything on the page true?" would have passed a page
listing three configuration parameters.

## The five checkers, and what each found on its first run

Three were built during this audit. Each takes a roster from the product and
refuses to agree with a hand-kept list.

| Checker | Roster from | First run |
|---|---|---|
| `docmap.py` | `BCOMP`'s tables | already green, 411 of 411 |
| `tclmap.py` | `newvoc` + the tier lists | red: five verbs undocumented, one documented verb that no longer exists |
| `confmap.py` | `config.c` | red: 19 of 52 parameters documented, one named that does not exist |
| `verbcounts.py` | `newvoc` + the tier lists | red: eleven wrong figures across six pages |
| `scriptmap.py` | the installed tree | red: 18 of 37 scripts undocumented |

### Two instrument defects, both caught before they reached a page

**`confmap.py` first called nine parameters inert**, three of them `GRPSIZE`,
`GRPDIR` and `USRDIR` — the default group size and the two directories every
account is created in. They are read from BASIC through `config('NAME')`, which
a C-only test cannot see. Widened to both languages.

Then both `CREATUSR` hits turned out to be **comments recording that the
parameter was removed**, so a note that it is dead read as evidence it is
alive. Comments are now stripped before matching.

**`verbcounts.py` first matched too loosely** — 28 figures found, 4 real.
"internal verb 29", "field 2 of a verb record" and "120 x 36" all matched. A
check whose output is mostly noise is one nobody reads, which is how `81`
survived for a week. Narrowed to a number immediately preceding plural "verbs".

Verdicts: **WRONG** — untrue of W1.0-0. **STALE** — true once. **UNWARRANTED** —
claims evidence it does not have. **CORRECT** — checked, no change needed.

### Encryption and SDEXT — `Administrator/04`, and the deleted `05`

| Claim | Verdict | Evidence |
|---|---|---|
| `sdencrypt(plaintext, key)` | WRONG | three arguments; the third is 201 hex or 202 base64 |
| a worked example using `'my-secret-key'` | WRONG | measured: returns nothing, `status()` 10204, key length |
| SDEXT provides hex and base64 encoding keys | WRONG | not implemented; those constants are `sdencrypt`'s third argument |
| two SDEXT keys listed | WRONG | ten are implemented, `KEYS.H:353-367` |
| SCRAM primitives "not called directly from SDBasic" | WRONG | they are keys 104–109 |
| `encrypt()`/`decrypt()` replaced by `sdencrypt()`/`sddecrypt()` | **CORRECT** | `BCOMP:36`, `:437`, `:566-567` |

**The finding that matters most on this page**: `sdext` is internal-only, so
the only route to a valid key is unavailable to an application. Field
encryption has no supported key route in W1.0-0, and the page now says so.

### Standard subroutines — `User/36`

Nine routines documented; three do not exist (`!OCONV`, `!ICONV`, `!SCREEN`)
and 36 that do were omitted. The real roster is 42, from the `$catalog`
declarations. Five of the documented ones are **functions** reached with
`deffun`, not subroutines reached with `call`.

### Client API — `User/37`

The two DLL names were called "second links, not file copies". They are
separate compiles of one source: same size, different SHA-256. Added where the
four DLLs are, the two supported ways to use them, and that `SDConnectLocal`
resolves `sd.exe` beside the loaded DLL — so a copy next to your own
application cannot make a local connection.

### Dictionary conversions — `User/34`

The worked-example table gave exact outputs for six pairs. Four were wrong.
Run as `tools/probes/p34-conversions.b`:

| Claimed | Measured |
|---|---|
| `D2/` on 20899 → `29/08/26` | `03/20/25` |
| `D` on 20899 → `29 Aug 2026` | `20 MAR 2025` |
| `MD2` on 1234567 → `1,234.56` | `12,345.67` |
| `ML` → `January` | `20899`, unchanged |

`ML` is a date-**mask** element used inside `D[...]`, not a conversion. Alone it
returns the value unchanged, so a reader following the table gets no error and
no conversion.

**The D-record field layout on `User/33` was checked against a real dictionary
record and is CORRECT** — `DATA.NAME` reads `D` / `2` / (empty) /
`DATA Pathname` / `18L` / `M`. Recorded so it is not re-checked.

### The tutorial — `User/40`

Six of the ten substantial programs did not compile; the 106-line application
had four errors. Full account in the commit and in
`tools/extract_programs.py`'s header. All ten compile with 0 errors now.

## Toolchain — three defects where the two authors' work met

Found by running the pipeline end to end for the first time. Each is a pair of
individually correct halves that had never been run in sequence.

1. **`release.ps1` refused every set** over `html/index.html`, a generated file
   with no markdown source. It is written by `add_nav.py`, which arrived with
   the second author's work; `release.ps1` predates set indexes. Exempted by
   name, not by pattern.
2. **`release.ps1` never ran `add_nav.py`.** Navigation existed only when
   somebody remembered, and a `-Force` render removed it again.
3. **Every set index linked back to the master index** — a 404 in every
   delivered copy, since sets are handed out individually. Removed rather than
   repointed: the standing rule is that sets never link out.

## Decisions taken during the audit

**q7, the `limitssh` question, closes as superseded rather than answered.** Two
different checkboxes were being conflated. The task that wrote `AllowGroups`
and `ForceCommand` stopped being a task on 21 Aug 2026; the machine the
question worried about no longer reaches the wizard, because `ssh-preflight.ps1`
refuses the install from `InitializeSetup`. Owner: *"We require the removal of
any ssh server prior to the initial install of SD. So the config is ours."*

**The hyphen spelling is documented rather than left as folklore.** SD accepts
`-` where a verb has `.`, deliberately (`CPROC:1499`). Measured with both
controls: `clear-select` runs, `zzz-nosuch` is refused, and `ct voc
create-account` reports not found, so it is the command processor's resolution
and not a second VOC record. An undocumented behaviour people rely on becomes a
compatibility constraint by accident.

**`Testing/` became `GettingStarted/`** and **the `Technical` set was
dissolved into `Administrator`**, both on the owner's ruling of 4 Sep 2026.
PRE_RELEASE 34 closes by removing the set rather than weakening the link check.

**Two of entry 80's own instructions were wrong and were corrected against the
code.** `ssh.server` with no keyword needs an elevated session — the guard at
`SSHSRVR:82` runs before the keyword parse. And `[locked]` is **not** honoured
on verbs: `LOGIN:1475` and message 10166 update a locked verb anyway and say
so, because field 3 of an internal verb record is a number and a reassignment
would dispatch it silently to a different function.
